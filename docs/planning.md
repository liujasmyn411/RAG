### 1.2 核心约束

- **事实准确性 > 人格一致性**：不能为了维持人设不顾事实
- **技术栈**：LangGraph + Neo4j + Milvus + PostgreSQL
- **特色资源**：四大名著向量库、红楼梦人物图谱
- **成本策略**：允许额外 LLM 调用用于记忆整理和风格校准

### 2.3 压缩策略

```
                    每轮对话结束
                         │
                         ▼
                ┌─────────────────┐
                │ 滑动窗口 ≥ 10 轮？│
                └────────┬────────┘
                         │
              ┌──────────┴──────────┐
              │ 否                   │ 是
              ▼                      ▼
         ┌────────┐        ┌─────────────────┐
         │ 保留全部 │        │ 语义触发判断      │
         │ 不做压缩 │        │ (小模型判断价值)   │
         └────────┘        └────────┬────────┘
                                    │
                         ┌──────────┴──────────┐
                         │ 有价值               │ 无价值/教务
                         ▼                      ▼
                  ┌────────────┐        ┌────────────┐
                  │ 生成摘要    │        │ 跳过摘要    │
                  │ 插入头部    │        │ 仅保留最近  │
                  └────────────┘        │ 1 次查询结果 │
                                        └────────────┘
```

**压缩规则汇总**：

| 数据类型 | 保留策略 | 例外 |
|---|---|---|
| 日常闲聊 | 10轮窗口 + 摘要 | — |
| 教务查询 | 不摘要，仅保留最近 1 次结果 | — |
| 心理危机 | 永久保留，不参与压缩 | 安全熔断最高优先级 |
| 业务数据 | 仅最近 1 次查询结果 | 不跨轮次持久化 |

#### 2.4.2 检测机制：两级过滤

```
用户消息到达
      │
      ▼
┌──────────────────┐
│ 第一级: 关键词+   │ 毫秒级, 不需要 LLM
│ 正则规则过滤      │
│                  │
│ · 已知敏感词库   │
│ · 脏话/侮辱词库  │
│ · Prompt注入模式 │
└────────┬─────────┘
         │
    ┌────┴────┐
    │ 命中     │ 未命中
    ▼          ▼
┌────────┐  ┌──────────────────┐
│ 直接    │  │ 第二级: LLM 语义  │ ~200ms, 小模型
│ 进入    │  │ 安全判断          │
│ 处理    │  │                  │
│ 流程    │  │ 判断消息是否包含:  │
└────────┘  │ · 政治敏感        │
            │ · 侮辱/歧视       │
            │ · Prompt注入      │
            │ · 骚扰/霸凌       │
            │                  │
            │ 输出 JSON:        │
            │ {risk_level,     │
            │  category,       │
            │  confidence}     │
            └────────┬─────────┘
                     │
                     ▼
              ┌──────────────┐
              │ 按分级处理    │
              └──────────────┘
```

**为什么需要两级？**
- 第一级拦截已知模式（毫秒级），避免让敏感内容流入 LLM 上下文
- 第二级处理变体/隐晦表达，关键词无法穷举

### 2.5 跨会话 State 继承机制

当会话因超时、显式结束或长时间中断而关闭后，下一次学生发消息时，需要根据 `carry_over_level` 初始化新的 State。核心问题是：**上次会话的什么内容、以什么形式、带到新会话中去。**

#### 2.5.1 会话关闭时的归档流程

会话关闭时必须同步生成归档包——不能依赖 Reflection（异步、不确定触发时间），下次会话可能在 Reflection 之前就启动了。

```

│  │   1. 讨论的主要话题                           │  │
│  │   2. 学生的关键信息和情绪变化                  │  │

│  │  提取并持久化:                                │  │
│  │  - crisis_flag + crisis_keywords            │  │
│  │  - violation_b1_count, violation_b2_count   │  │
```

#### 2.5.4 rolling_summary 的演化

每次会话关闭时，将本次摘要与旧摘要合并蒸馏，始终只保留一个浓缩版本：

```
本次会话摘要 + 旧 rolling_summary
           │
           ▼
      LLM 合并蒸馏:
      · 旧会话细节逐渐被压缩
      · 稳定的认知 (如"数学偏弱") 持续保留
      · 过时信息 (如"明天要考试") 自动淘汰
      · 最多保留最近 5 次会话的关键点
      · 总长度 ≤ 300 字
           │
           ▼
      新 rolling_summary (存入 student_profile 表)

示例演化:
  第1次后: "小红, 首次互动5/20。数学偏弱, 函数图像困难。"
  第3次后: "小红, 互动3次。数学偏科(几何好代数弱), 
           有考前焦虑, 情绪受成绩影响大。最近讨论函数图像。"
  第8次后: "小红, 老用户(8次)。数学偏科已有改善, 焦虑减轻。
           近期话题: 语文写作、同伴关系、期末考试准备。"
```

#### 2.5.8 关键设计决策

| 决策 | 结论 | 原因 |
|---|---|---|
| full 级别 L1 事实是否保留 | 清零，每次重新获取 | 事实数据可能过旧 |
| rolling_summary 更新时机 | 会话关闭时同步生成 | 下次会话可能在 Reflection 之前 |
| 关系强度注入方式 | 自然语言，放入人设增强包 | 不给 LLM 暴露"数字" |
| 归档摘要 vs Reflection | 归档摘要是会话级，Reflection 是认知级 | 两者不重复，各有用途 |

#### 2.6.4 数据隔离的工程实现

**Milvus: student_id 作为 Partition Key**

```
为什么必须是 Partition Key 而非普通过滤?

  方案 A (普通标量过滤):
    expr = "student_id == 'XH_2024001'"
    ANN 检索 → 全库扫描 → 过滤
    100学生 × 3650条 = 365,000 条里做 ANN
    过滤是 post-ANN, 本学生的 top_k 可能被别学生挤掉

  方案 B (Partition Key, 推荐):
    partition_name = f"student_{student_id}"
    ANN 检索 → 仅在该分区内搜索
    每分区 ~3650 条, 天然隔离, 不可跨学生
    性能不随学生总数增长

  辅导员查 L3: 不允许
    → 代码层拦截: user_role=teacher → 拒绝对 L3 的查询
```

**Neo4j: 三层防护防"走错边"**

```
Layer 1: 代码规约
  所有涉及 Student 的查询必须带:
  MATCH (s:Student {id: $student_id})
  然后从 s 出发扩展, 禁止跨学生 MATCH

Layer 2: Neo4j 约束
  · Student.id 唯一索引
  · 学生节点 LABEL 含班级: Student:Class3 (方便班级级查询)
  · 查询模板封装为 DAO, 不裸写 Cypher

Layer 3: 应用层校验
  DAO 函数签名自动注入 student_id:
  def get_l2_traits(student_id, user_role):
      if user_role == "student":
          assert student_id == current_user.id
      elif user_role == "teacher":
          assert student_id in get_my_students()

跨学生分析的正确做法:
  · 先聚合 → 再返回
  · MATCH ... RETURN trait, count(*) → "数学偏科中: 焦虑41%"
  · 永不在跨学生查询中返回单个学生 ID
```

**LangGraph: thread_id 与 session_id 的映射**

```
carry_over = full (续接):
  thread_id 复用上一个 session 的 thread_id
  → checkpointer 自动加载完整 State 历史
  → 按我们的 carry_over 逻辑裁剪 messages

carry_over = partial / minimal (新会话):
  新 thread_id = 新 session_id
  → 全新的 checkpointer State
  → 手动从 PG session_archive 加载数据

thread_session_map 表 (PG):
┌──────────────────────────────────────────────────────────┐
│  session_id, thread_id, student_id, user_role,           │
│  carry_over (full|partial|minimal), created_at, closed_at│
└──────────────────────────────────────────────────────────┘
```

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  ┌─────────────────────┐    ┌─────────────────────────────┐  │
│  │  L3-Hot (Milvus)     │    │  L3-Cold (PG JSONB)          │  │
│  ├─────────────────────┤    ├─────────────────────────────┤  │
│  │ 存: 结构化摘要        │    │ 存: 原始对话全文              │  │
│  │ 查: 每次检索都用       │    │ 查: 仅审计/抽查/重处理       │  │
│  │ 删: 跟遗忘衰减        │    │ 删: Day30温归档→Day90删除     │  │
│  │ LLM注入: YES         │    │ LLM注入: NO                 │  │
│  │ Reflection: YES      │    │ Reflection: 仅在重处理时     │  │
│  └─────────────────────┘    └─────────────────────────────┘  │
│                                                              │
│  1. Cold 先写, Hot 异步提取, 写入顺序不反过来                  │
│  2. Hot 挂了不影响 Cold, Cold 挂了是 PG 故障→整个系统停        │
│  3. 检索走 Hot, 审计走 Cold, 两条链路互不阻塞                  │
│  4. Cold 过期删除后 Hot 不受影响                              │
│  5. 提取失败有四级兜底, 最坏情况=没有 Hot, 系统仍能运行         │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 5. 遗忘机制：双轨衰减（已确认）

### 5.1 软遗忘：指数衰减模型

**衰减公式**：

```
score_final = score_base × importance × e^(-λ × days) × reinforce_count
                    │          │          │              │
                    │          │          │              └── 检索加成
                    │          │          └── 衰减曲线 (核心)
                    │          └── 事件重要性系数
                    └── 入库初始分
```

**不同重要性下的衰减曲线**：

```
记忆分数
  1.0 ┤
      │  crisis (imp=1.0, λ=0)  ════════════════════════════════════
      │                             永不衰减
      │
      │  emotional (imp=0.7, λ=0.01) ──────────────────
  0.6 ┤                                 缓慢衰减       ───
      │
      │  daily_chat (imp=0.2, λ=0.02)  ────────
  0.4 ┤                                 中速衰减
      │
      │  academic (imp=0.05, λ=0.05)  ────
  0.2 ┤                                 快速衰减
      │
  0.0 ┼────┬────┬────┬────┬────┬────┬────┬────┬────
      0    7    14   21   28   35   42   49   56  天数
```

**参数对照表**：

| 记忆类型 | importance | λ (衰减速率) | 半衰期 | 说明 |
|---|---|---|---|---|
| 心理危机 | 1.0 | 0 | ∞ | 永不衰减，免于软遗忘和硬遗忘 |
| 情绪波动 | 0.7 | 0.01 | ~69 天 | 慢衰减 |
| 日常闲聊 | 0.2 | 0.02 | ~35 天 | 中等衰减 |
| 教务查询 | 0.05 | 0.05 | ~14 天 | 快速衰减 |

### 5.3 Neo4j 关系边衰减

```
关系强度
  1.0 ┤ ●
      │  │╲
  0.8 ┤  │ ╲
      │  │  ╲
  0.6 ┤  │   ╲
      │  │    ╲
  0.4 ┤  │     ╲
      │  │      ╲_____
  0.2 ┤  │
      │  │
  0.0 ┼──┼────┬────┬────┬────┬────
      0  7    14   21   28   35  天数
      ↑                      ↑

    强度 0.9            降至 ~0.3
```

**公式**：

```
关系强度 = 初始权重 × e^(-λ × days_since_last_interaction)

学生互动频率修正:
  - 高频学生 (每天对话): λ=0.005 (慢衰减，关系稳固)
  - 中频学生 (每周对话): λ=0.01  (正常衰减)
  - 低频学生 (月更):     λ=0.02  (快衰减，关系淡化)
```

### 6.4 第三层：一致性置信度 (连续贝叶斯更新)

> 此分值衡量"信念的确信程度"，是贝叶斯更新的结果，与前两层分值语义不同。

**更新公式**：

```
C_new = C_old + Δ

支持: Δ = quality × direction × novelty_decay × (1 - C_old)
反对: Δ = quality × direction × novelty_decay × C_old

其中:
  quality:       证据质量 (来自写入置信度)
  direction:     +1 支持 / -1 反对
  novelty_decay: e^(-0.01 × days_since_evidence)
  (1-C_old):     边际递减 — 越确信越难再提升
  C_old:         边际递减 — 越确信越容易被动摇(幅度大)
```

**置信度收敛过程可视化**：

### 6.6 置信度动力学：抗扰动、连续性、长默回升

6.3 的基础贝叶斯更新公式解决了"如何从证据更新信念"。但缺三个现实场景的处理：

- 已确立的信念不应该被一条弱证据轻易动摇（抗扰动）
- 连续出现相同矛盾信号比分散出现更值得警惕（连续性惩罚）
- 长期没有再提的冲突，信念应有部分回升（长默回升）

#### 6.6.1 机制一：高置信度抗扰动 (Resistance)

**问题**：基础公式下，一条 D 级弱证据（quality=0.5）反对 C=0.92 的已确立信念：

```
Δ = 0.5 × (-1) × 1.0 × 0.92 = -0.46
C_new = 0.92 - 0.46 = 0.46  // 已确立 → 弱假设，不合理
```

**改进**：引入抗扰动系数 `resistance(C)`，置信度越高，越难被动摇。

```
resistance(C) = (C - 0.35) / 0.65,  截断到 [0, 0.85]

Δ_effective = Δ_base × (1 - resistance(C_old))
```

```
抗扰动曲线:

resistance
  1.0 ┤                          ┌────── (上限 0.85)
      │                       ╱
  0.8 ┤                    ╱
      │                 ╱
  0.6 ┤              ╱
      │           ╱
  0.4 ┤        ╱
      │     ╱
  0.2 ┤  ╱
      │╱
  0.0 ┼───┬────┬────┬────┬────┬────
     0.35 0.5  0.6  0.7  0.8  0.9  1.0   C
          │    │    │    │    │    │
        0.23  0.38 0.54 0.69 0.77 0.85   resistance
```

**效果对比**：

```
C_old = 0.92, 一条 D 级 (0.5) 反对证据:

改进前: C_new = 0.46  // 不合理

改进后:
  resistance = min((0.92 - 0.35) / 0.65, 0.85) = 0.85
  Δ_effective = -0.46 × (1 - 0.85) = -0.069
  C_new = 0.92 - 0.069 = 0.851  // 仍是强信念

多条 D 级连续反对:
  第1条: 0.92 → 0.851
  第2条: 0.851 → 0.793
  第3条: 0.793 → 0.746
  第5条: ≈ 0.672
  → 5 条 D 级连续反对才能将已确立拉到中等信念
  → 合理: 连续 5 次对话都指向反方向, 旧信念确实应该被质疑
```

**一条高质量反证的威力**：

```
C_old = 0.92, 一条 S 级 (0.95) 反对证据:

  resistance = 0.85
  Δ_base = 0.95 × (-1) × 1.0 × 0.92 = -0.874
  Δ_effective = -0.874 × 0.15 = -0.131
  C_new = 0.92 - 0.131 = 0.789

→ S 级反对证据一击将已确立拉到强信念下沿
→ 不会一击打爆, 但造成实质动摇
```

#### 6.6.2 机制二：连续性累积惩罚 (Streak Penalty)

**问题**：现有模型下，三条相同反对证据各自独立计算 Δ。由于边际递减（C 越低 Δ 越小），后面的反对越来越"不疼"。但连续出现相同矛盾信号，比分散出现更值得警惕。

**改进**：连续同向证据获得递增乘数。

```
streak_multiplier = 1 + (streak_count - 1) × 0.35,  上限 2.5

Δ_final = Δ_effective × streak_multiplier
```

```
streak_count   multiplier   说明
────────────   ──────────   ────
1 (首次)        1.00         正常权重
2 (连续第2次)   1.35         增幅 35%
3 (连续第3次)   1.70         增幅 70%
4 (连续第4次)   2.05         增幅 105%
5+             2.50         上限, 不再增加
```

**"连续性"的定义**：中间没有出现相反方向的证据。如果反对→支持→反对，streak 重置。

```
证据序列:  反₁ → 反₂ → 支₁ → 反₃ → 反₄ → 反₅
streak:     ×1    ×1.35   重置   ×1    ×1.35  ×1.70
```

**效果对比**：

```
C_old = 0.80, 连续 3 次 D 级反对:

无连续性:
  反₁: C = 0.80 → 0.735
  反₂: C = 0.735 → 0.685
  反₃: C = 0.685 → 0.647
  总降幅: 0.153

有连续性:
  反₁ (×1.0):  C = 0.80 → 0.735
  反₂ (×1.35): C = 0.735 → 0.663
  反₃ (×1.70): C = 0.663 → 0.576
  总降幅: 0.224

→ 连续性惩罚让总降幅增加约 50%
→ "同一个矛盾重复出现"本身就是强信号
```

**抗扰动 + 连续性协同**：

```
C_old = 0.92 (极高), 连续 3 次 D 级反对:

单独抗扰动:  3次后 ≈ 0.75
抗扰动+连续性:
  反₁: 0.92 → 0.851  (Δ=-0.069 × 1.0)
  反₂: 0.851 → 0.758 (Δ=-0.093 × 1.35)
  反₃: 0.758 → 0.638 (Δ=-0.120 × 1.70)
  3次后: 0.638

→ 单次 D 级无法撼动已确立信念 (抗扰动保护)
→ 连续 3 次 D 级会显著削弱它 (连续性惩罚)
→ 符合直觉: 一个人偶尔说错话无所谓, 连续三次值得认真对待
```

#### 6.6.3 机制三：长期沉默后的置信度回升 (Recovery with Scar)

**问题**：

```
C_peak = 0.85 ("小红语文不错")
Day1: 一条反对证据 → C 降到 0.68
Day2~Day30: 没有任何关于"语文"的讨论

Day31 的置信度应该是多少?
  · 还是 0.68? (反对是 30 天前的, 可能只是那天心情不好)
  · 回到 0.85? (既然再也没人提, 可能反对是噪声)
```

**改进**：追踪伤害深度，部分回升，但留有永久疤痕。

```
追踪:
  C_peak:   遇到第一次反对之前的最高置信度
  C_trough: 被反对后降到的最低点
  damage = C_peak - C_trough  // "伤害深度"

回升公式:
  recovery = damage × (1 - e^(-λ × silence_days)) × recovery_cap

  λ = 0.05           (回升速率)
  recovery_cap = 0.70 (最多恢复 70% 的损伤, 30% 是永久疤痕)

  C_current = C_trough + recovery
```

```
回升曲线:
```

#### 6.6.4 三个机制联合作用的完整示例

```
场景: "小红语文不错" C_peak = 0.85

Day1   反对₁ (D级, quality 0.5)
       resistance = (0.85-0.35)/0.65 = 0.77
       Δ = 0.5×(-1)×1.0×0.85×(1-0.77)×1.0 = -0.098
       C = 0.85 - 0.098 = 0.752
       streak=1, C_trough=0.752

Day3   反对₂ (D级, 连续)
       resistance = 0.618, streak=1.35
       Δ = 0.5×(-1)×1.0×0.752×(1-0.618)×1.35 = -0.194
       C = 0.752 - 0.194 = 0.558
       streak=2, C_trough=0.558

Day8   反对₃ (D级, 继续连续)
       resistance = 0.32, streak=1.70
       Δ = 0.5×(-1)×1.0×0.558×(1-0.32)×1.70 = -0.322
       C = 0.558 - 0.322 = 0.236
       streak=3, C_trough=0.236

       ★ 三条连续 D 级: 0.85 → 0.236 (不确定)
       ★ 无抗扰动: 0.85 → 0.46 → 0.28 → 0.18
       ★ 有抗扰动+连续性: 0.85 → 0.75 → 0.56 → 0.24
       ★ 二者差距不大 (连续性加成抵消了抗扰动保护), 合理

Day8~Day38  30 天无讨论

       damage = 0.85 - 0.236 = 0.614
       recovery = 0.614 × (1-e^(-1.5)) × 0.70 = 0.334
       C = 0.236 + 0.334 = 0.570
       → 回升到弱~中等信念, 远回不到 0.85

Day38~Day68  又30天

       recovery = 0.614 × (1-e^(-3.0)) × 0.70 = 0.408
       C = 0.236 + 0.408 = 0.644
       → 接近回升上限 0.666

Day120 支持₁ (A级, quality 0.90)
       resistance = 0.48, C=0.660
       Δ = 0.90×(+1)×(1-0.660)×(1-0.48)×1.0 = +0.159
       C = 0.660 + 0.159 = 0.819
       → 一条高质量正面证据大幅拉升, 但疤痕不会消失
```

#### 6.6.5 完整公式汇总

```
C_new = C_old + Δ_final

Δ_final = Δ_base × (1 - resistance) × streak_multiplier

Δ_base = quality × direction × novelty_decay × 
         (1 - C_old)   // 支持
         C_old         // 反对

resistance(C) = (C - 0.35) / 0.65,  截断 [0, 0.85]

streak_multiplier = 1 + (streak_count - 1) × 0.35,  上限 2.5
  (仅同方向连续时生效, 方向改变时 streak 重置)

回升 (仅在 streak=0 且 silence_days > 0 时生效):
  recovery = damage × (1 - e^(-0.05 × silence_days)) × 0.70
  C = C_trough + recovery
  上限 = C_peak - damage × 0.30  (= C_peak - 永久疤痕)
```

### 8.4 检索增强策略

检索增强是记忆系统对外暴露的统一接口。核心要解决：**不同情境查什么、怎么查、查完怎么拼。**

#### 8.4.1 三种情境的检索策略矩阵

```
          L0(Neo4j)  L1(PG)   L2(Neo4j)  L3-Hot(Milvus)  L3-Cold(PG)
          ────────   ──────   ────────    ──────────────   ──────────
daiyu       ✅        ✗         ✅           ✅               ✗
academic    ✗        ✅         ✅(默认)     ✗               ✗
psych       ✗        ✗         ✅           ✗               ✅

daiyu_chat:     L3 近期记忆 > L2 抽象认知 > L0 角色背景
                需要丰富上下文, 让黛玉"有得聊"
academic_query: L1 精确数据 > L2 学科认知(辅助解释)
                需要精确, 最少记忆干扰
psych_crisis:   L2 危机历史 + L3-Cold 原文回源
                安全干预, 无角色扮演
```

#### 8.4.6 检索失败的降级策略

```
L3 Milvus 失败:
  → 跳过 L3, 仅用 L2 + L0
  → 黛玉自然表现, 不提及系统异常
  → 日志记录降级

L2 Neo4j 失败:
  → 跳过 L2, 用 L3 + L0
  → 黛玉失去长期认知, 但仍有近期记忆

L0 Neo4j 失败:
  → 跳过 L0, 仅用风格 Prompt + L2 + L3
  → 口吻仍在, 缺红楼典故

Reranker 失败:
  → 直接用 Milvus ANN 原始分数排序
  → 仍走三档分拣

全部失败:
  → 仅用风格 Prompt + 当前消息
  → 黛玉: "这会子我脑子里乱得很, 你且说些别的罢。"
  → 用黛玉"善忘/娇弱"特征合理化异常
```

#### 8.4.7 retrieve_memories 节点实现骨架

```python
def retrieve_memories(state: AgentState) -> dict:
    intent = state["current_intent"]
    query = state["messages"][-1].content
    sid = state["student_id"]

    if intent == "daiyu_chat":
        return _retrieve_daiyu_chat(query, sid)
    elif intent == "academic_query":
        return _retrieve_academic(query, sid)
    else:  # psych_crisis
        return _retrieve_psych_crisis(query, sid)

def _retrieve_daiyu_chat(query, sid):
    # Phase 1: 快速提取 (并行)
    l2_tags = safe_call(neo4j.get_l2_tags, sid) or {}
    emotions = safe_call(haiku_classifier.classify, query) or {}

    enhanced = f"{query}。该生特征: {l2_tags}。情绪: {emotions}"

    # Phase 2: 深度检索 (并行)
    l3_raw = safe_call(milvus.search, enhanced,
                       partition=f"student_{sid}",
                       filter=emotions.get("emotion_primary"),
                       top_k=20) or []
    l3_ranked = safe_call(reranker.rerank, query, l3_raw) or l3_raw
    l3_final = filter_by_confidence(l3_ranked)[:5]

    l0_scenes = safe_call(neo4j.get_scenes, emotions, limit=2) or []

    # Phase 3: 合并
    merged = merge_and_dedup(l3_final, l2_tags, l0_scenes,
                             budget={"L3": 1000, "L2": 600, "L0": 400})
    return {"retrieved_context": merged}

def safe_call(fn, *args, **kwargs):
    """容错包装: 失败 → None + 记录降级日志"""
    try:
        return fn(*args, **kwargs)
    except Exception as e:
        log_degradation(fn.__name__, e)
        return None
```

### 8.6 Neo4j 图模型 Schema

#### 8.6.1 图模型全貌

```
┌──────────────────────────────────────────────────────────────┐
│                    Neo4j 图模型全景                            │
│                                                              │
│  ┌─────────────────────────┐    ┌─────────────────────────┐  │
│  │       L0 角色本体        │    │      L2 语义认知          │  │
│  │   (共享, 只读)           │    │   (按学生隔离)            │  │
│  │                         │    │                         │  │
│  │  (:Character) 人物节点   │    │  (:Student)             │  │
│  │    ├──[:RELATED_TO]→    │    │    ├──[:偏科]→(:Subject) │  │
│  │    ├──[:APPEARS_IN]→    │    │    ├──[:情绪倾向]→(:Trait)│  │
│  │    │    (:Scene) 名场面  │    │    ├──[:态度偏好]→(:Subject)│ │
│  │                         │    │    └──[:社交模式]→(:Trait)│  │
│  │  人物关系: 倾慕/忌惮/依赖 │    │                         │  │
│  │  场景标签: emotion_tag   │    │  冲突边维护在关系属性中    │  │
│  └─────────────────────────┘    └─────────────────────────┘  │
│                                                              │
│  跨层桥接:                                                    │
│  (:Character {name:"林黛玉"})-[:关心 {strength,...}]→(:Student)│
└──────────────────────────────────────────────────────────────┘
```

#### 8.6.2 节点类型

**L0 节点**:

```
Character (红楼梦人物):
  id, name, aliases[], role, traits[], residence, importance
  约束: CREATE CONSTRAINT FOR (c:Character) REQUIRE c.id IS UNIQUE

Scene (名场面):
  scene_id, scene_name, chapter, emotion_tag, emotion_tags[],
  characters[], scene_type, trigger_tag, key_quote,
  summary(≤100字), response_hint
  约束: CREATE CONSTRAINT FOR (s:Scene) REQUIRE s.scene_id IS UNIQUE
  索引: CREATE INDEX FOR (s:Scene) ON (s.emotion_tag)
```

**L2 节点**:

```
Student:
  LABEL: Student:Class{班级名} (多标签, 方便班级级查询)
  student_id, name, class, teacher_id, created_at
  约束: CREATE CONSTRAINT FOR (s:Student) REQUIRE s.student_id IS UNIQUE

Subject (共享节点, 所有学生共用):
  name (唯一, "数学"/"语文"/...)
  约束: CREATE CONSTRAINT FOR (sub:Subject) REQUIRE sub.name IS UNIQUE

Trait (共享节点, 预建 10~15 个 + 允许动态新增):
  name (唯一, "考前焦虑"/"社交回避"/"自我否定"/...),
  category ("emotion"|"social"|"behavior")
  约束: CREATE CONSTRAINT FOR (t:Trait) REQUIRE t.name IS UNIQUE
```

#### 8.6.3 关系类型

```
L0 关系:
  (:Character)-[:RELATED_TO {type, strength}]→(:Character)
    type ∈ {倾慕,依赖,忌惮,信赖,敬畏,母女,父子,姐妹,主仆,知己}
    strength ∈ [0,1]

  (:Character)-[:APPEARS_IN {role}]→(:Scene)
    role: "protagonist"|"supporting"|"mentioned"

L2 关系 (每条边携带完整置信度字段):
  (:Student)-[:偏科 {level, trend, confidence, C_peak,
                     C_trough, streak_count, streak_direction,
                     last_oppose_time, source, verified_count,
                     created_at, updated_at}]
            →(:Subject)

  (:Student)-[:情绪倾向 {intensity, confidence, C_peak,
                         C_trough, streak_*, ...}]
            →(:Trait)

  (:Student)-[:态度偏好 {valence, confidence, C_peak,
                         C_trough, streak_*, ...}]
            →(:Subject)

  (:Student)-[:社交模式 {pattern, confidence, C_peak,
                         C_trough, streak_*, ...}]
            →(:Trait)

跨层桥接:
  (:Character {name:"林黛玉"})
    -[:关心 {strength, first_interaction, last_interaction,
             interaction_count}]
    →(:Student)
  strength: 关系强度 [0,1], 每日定时衰减
```

#### 8.6.4 关系边的置信度动力学字段

```
所有 L2 关系边携带 (部分字段可能为 null 在无冲突时):

  confidence:         FLOAT  当前 C
  C_peak:             FLOAT  最高值
  C_trough:           FLOAT  最低值
  streak_count:       INT    连续同向数
  streak_direction:   STRING  "support"|"oppose"|null
  last_oppose_time:   DATETIME
  source:             STRING  来源 (C级/D级/Reflection)
  verified_count:     INT    被验证次数
  created_at/updated_at: DATETIME
```

#### 8.6.5 核心查询

```cypher
// daiyu_chat: 学生 L2 认知 (1-hop)
MATCH (s:Student {student_id: $sid})-[r]-(t)
WHERE type(r) IN ['偏科','情绪倾向','态度偏好','社交模式']
RETURN type(r), t.name, r.confidence, r.C_peak, r.streak_direction
ORDER BY r.confidence DESC;

// daiyu_chat: 黛玉人物子图
MATCH (daiyu:Character {id: "char_daiyu"})-[r:RELATED_TO]-(o)
RETURN type(r), r.strength, o.name, o.traits;

// daiyu_chat: 情绪匹配名场面 (随机轮换)
MATCH (s:Scene) WHERE s.emotion_tag = $emotion
RETURN s.scene_name, s.key_quote, s.response_hint
ORDER BY rand() LIMIT 2;

// 教师: 单个学生画像
MATCH (s:Student {student_id: $sid})
OPTIONAL MATCH (s)-[r1:偏科]->(subj)     OPTIONAL MATCH (s)-[r2:情绪倾向]->(tr)
OPTIONAL MATCH (s)-[r3:态度偏好]->(subj2) OPTIONAL MATCH (daiyu)-[rc:关心]->(s)
RETURN s, r1, subj, r2, tr, r3, subj2, rc;

// 教师: 班级聚合 (不返回单生 ID)
MATCH (s:Student:Class3)-[r:情绪倾向]->(t:Trait)
WHERE t.category = "emotion"
RETURN t.name, count(s) AS cnt ORDER BY cnt DESC;

// 重连: 关系强度
MATCH (:Character {id:"char_daiyu"})-[r:关心]->(:Student {student_id:$sid})
RETURN r.strength, r.last_interaction, r.interaction_count;
```

#### 8.6.6 设计决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 认知存储方式 | 关系边 (非 Cognition 节点) | 初期简单, 查询一跳到位; 后续按需迁移 |
| Trait 节点管理 | 预建 10~15 核心 + 动态新增 | 兼顾覆盖面和灵活性 |
| 关心边衰减 | 定时任务每日更新 strength | 跟随遗忘机制统一调度 |
| 冲突追踪 | 冲突信息存于关系边属性 | 避免过早引入中间节点 |
| 学生隔离 | student_id 属性 + Cypher WHERE | 配合代码层 DAO 校验 |

### 8.7 Reflection 节点设计

Reflection 是整个记忆系统的核心提炼引擎——将碎片化的 L3 情景快照提炼为 L2 语义认知。

#### 8.7.1 触发与定位

```
触发条件: (unprocessed_l3_count ≥ 5) OR (hours_since_last > 168) OR (存在危机 L3)

每次对话结束 → post_process → L3 入库 → 计数+1 → 检查触发
  · 危机 L3: 立即触发 (不攒批, 安全优先)
  · 普通 L3: 等待门槛触发
  · 未命中: L3 继续堆积, 不阻塞对话流

节点位置: LangGraph 异步节点, 不阻塞用户回复
```

#### 8.7.2 六步工作流程

```
Step 1: 拉取未处理 L3-Hot
┌──────────────────────────────────────────────────────┐
│  Milvus: WHERE student_id=X AND processed_for_l2     │
│          IN ('false','skipped')                       │
│           AND archived=F                             │
│          ORDER BY timestamp ASC, LIMIT 30            │
│  设计决策: 上限 30 条拉取, 每组最多 15 条喂给 LLM     │
└──────────────────────────────────────────────────────┘

Step 2: 按 topic 聚类
┌──────────────────────────────────────────────────────┐
│  L3-Hot 自带 topic 字段, 天然分组                     │
│  每组 ≥ 2 条才触发提炼 — 单条推断不可靠               │
│  例外: 心理危机 (topic=self_harm) 1 条也处理          │
│  不足 2 条的同 topic → 标记 skipped, 等攒够再处理     │
└──────────────────────────────────────────────────────┘

Step 3: LLM 提炼候选 L2 认知
┌──────────────────────────────────────────────────────┐
│  输入: N 条 L3 结构化摘要                             │
│  输出: JSON [{dimension, target, relation_type,      │
│              content, trend/intensity,                │
│              source_type:"reflection",                │
│              evidence_ids[], contradiction_noted}]   │
│  提取维度: 学科能力/情绪模式/社交模式/态度偏好         │
│  置信度: C 级 0.70 (Reflection 跨对话提炼)           │
│  约束: 无 evidence (≥2条L3) 不提, 不编造              │
└──────────────────────────────────────────────────────┘

Step 4: 查找 Neo4j 现存 L2
┌──────────────────────────────────────────────────────┐
│  MATCH (s:Student {id:X})-[r]-(t)                    │
│  WHERE type(r) IN ['偏科','情绪倾向','态度偏好',       │
│                    '社交模式']                        │
│  返回现存边的所有属性 (含三因子置信度字段)              │
└──────────────────────────────────────────────────────┘

Step 5: 冲突分类 + 三因子更新
┌──────────────────────────────────────────────────────┐
│  对每条候选 L2 与现存 L2 做语义比对:                   │
│  · 新认知 → 创建关系边 (conf=0.70, C级)              │
│  · 支持现有 → 连续贝叶斯更新 (resistance+streak)     │
│  · 冲突 → 六分类分流 → 各自对应操作                  │
│  更新关系边的三因子字段: confidence/C_peak/C_trough/   │
│  streak_count/streak_direction/last_oppose_time      │
└──────────────────────────────────────────────────────┘

Step 6: 事务写入 + 标记已完成
┌──────────────────────────────────────────────────────┐
│  BEGIN TX → Neo4j 更新/创建 → Milvus 标记已处理 → COMMIT│
│  │  processed_for_l2 = 'true' (importance 不动, 仍可检索) │
│  失败 → ROLLBACK → 记录日志 → 下次重处理               │
└──────────────────────────────────────────────────────┘
```

#### 8.7.4 更新操作 Cypher

```
新认知 (无冲突):
  MATCH (s:Student {student_id:$sid}), (t:Subject {name:"数学"})
  CREATE (s)-[r:偏科]->(t)
  SET r.level=$content, r.trend=$trend, r.confidence=0.70,
      r.C_peak=0.70, r.source="reflection",
      r.verified_count=1, r.streak_count=1,
      r.streak_direction="support", r.created_at=datetime();

支持现有 (连续贝叶斯):
  MATCH (s:Student {student_id:$sid})-[r:偏科]->(t:Subject {name:"数学"})
  SET r.confidence = r.confidence + $delta,
      r.C_peak = CASE WHEN r.confidence > r.C_peak
                      THEN r.confidence ELSE r.C_peak END,
      r.streak_count = r.streak_count + 1,
      r.verified_count = r.verified_count + 1,
      r.updated_at = datetime();

类型一 直接对立 (streak 方向变更):
  SET r.confidence = r.confidence + $delta_oppose,
      r.C_trough = CASE WHEN r.confidence < r.C_trough
                        THEN r.confidence ELSE r.C_trough END,
      r.last_oppose_time = datetime(),
      r.streak_count = 1,
      r.streak_direction = "oppose",
      r.updated_at = datetime();

类型三 范围细化:
  SET r.level = $refined_content,
      r.confidence = r.confidence - 0.05,
      r.updated_at = datetime();
```

#### 8.7.5 特殊场景

```
新学生 (L3 全不同 topic):
  每个 topic 仅1条 → 跳过本次 → 标记 skipped → 等攒够
  不强行提炼单条 (危机除外)

危机立即触发:
  → 拉取该学生所有未处理 L3
  → 重点提炼情绪模式和心理风险
  → 仅 1 条也处理 (安全优先于质量标准)

堆积 30+ 条同一 topic:
  → 取最近 15 条提炼
  → 剩余标记 batched, 下次 Reflection 再处理
  → 避免单次 LLM 输入过大
```

#### 8.7.6 定时维护任务 (每日凌晨)

```
任务 1: 遗忘衰减
  · Neo4j [:关心] 边 strength 按 e^(-λ×days) 衰减
  · Milvus L3 importance 同步衰减

任务 2: 回升计算
  · 扫描 streak_count=0 且 damage>0 的 L2 关系边
  · recovery = damage × (1-e^(-0.05×silence_days)) × 0.70
  · 更新 confidence = C_trough + recovery

任务 3: 超时归档
  · 矛盾悬挂 > 30 天 → 双方归档
  · L3-Cold > 90 天 → 删除原文 (危机除外)

任务 4: 兜底触发
  · 扫描 unprocessed_l3_count > 0 且 last_reflection > 7 天
  · → 强制触发 Reflection
```

#### 8.7.7 设计决策

| 决策 | 选择 | 原因 |
|---|---|---|
| 单次拉取上限 | 30 条拉取 / 15 条喂 LLM | 1500字输入, LLM 轻松处理 |
| 提炼最低门槛 | 同 topic ≥ 2 条 | 单条不可靠, 需要交叉验证 |
| 危机例外 | 1 条也处理 | 安全优先于质量标准 |
| L3 标记策略 | processed_for_l2='true', importance 不动 | 提炼后 L3 仍可检索 |
| 事务策略 | 一个 Reflection 批次 = 一个 DB 事务 | 失败回滚, 下次重处理 |

## 10. 关键技术约束备忘

- **心理安全熔断**：识别到自伤/重度抑郁关键词时，立即绕过黛玉人设，切换标准干预话术并通知辅导员
- **风格校准**：允许额外 LLM 调用成本用于 Self-Correction Loop，确保回复符合黛玉口吻（半文半白、避免客服用语）
- **情节预处理**：红楼文本需提前用 LLM 批量标注 `{scene, emotion, trigger, response_style, key_quote}`，构建情绪索引后再入库
- **Reranker 成本**：每条检索多一次 Cross-Encoder 调用（约 50-200ms），可接受
- **事实优先原则**：事实决定黛玉"说什么"，人格只决定"怎么说"。A 级系统数据永远覆盖 S 级用户自述
