# 四大名著 → Milvus 向量知识库 实施计划

## 目标
将项目中 4 部 txt 小说切片后，用 `BAAI/bge-large-zh-v1.5` 向量化，存储到 Docker 部署的 Milvus 中，支持语义检索。

## 文件摸底结果

| 书名 | 格式 | 章节数 | 特点 |
|------|------|--------|------|
| 《三国演义》 | HTML（含 `<p>` 标签） | 110 回 | 有版权头、简介、正文标记 |
| 《水浒传》 | HTML（含 `<p>` 标签） | 楔子 + 回目 | 章节标题格式含冒号，如"楔子:张天师..." |
| 《西游记》 | 纯文本 | 99 回 | 有前 5 行版权/网站声明 |
| 《红楼梦》 | 纯文本 | 121 回 | 已转 UTF-8，格式最干净 |

## 实施步骤

### Step 1：环境准备
- **Milvus Docker**：确认 Milvus Standalone 容器已启动（默认端口 19530 + 9091）
- **Python 依赖**：`pymilvus`、`sentence-transformers`
- **本地模型**：`./models/bge-large-zh-v1.5/`（已就绪）

### Step 2：文本预处理
1. **读取文件**：逐行读取 4 个 txt
2. **清洗操作**：
   - 去掉版权头（前 5 行网站声明）
   - 去掉 HTML `<p>` 标签（三国、水浒）
   - 去掉空行
3. **章节解析**：按回目标题正则切分，提取章节名 + 章节正文

### Step 3：文本切片
- **策略待定**（见下方【不确定点 2】）
- 候选方案：
  - **A. 按章节整回目切**：每回一个 chunk，语义最完整，但部分长章节可能超 512 token
  - **B. 固定长度滑动窗口**：如 500 字符 / chunk，重叠 50 字符，粒度细但可能切断语义
  - **C. 混合策略**：先按章节切，单章超过 800 字符再按段落二次切分

### Step 4：向量化
- 加载本地 `bge-large-zh-v1.5`（1024 维）
- 批量编码（batch_size=32）
- 是否加检索前缀指令：`为这个文档生成表示以用于检索：`

### Step 5：Milvus Collection 设计
- **Collection 名称**：`sida_mingzhu`（或用户指定）
- **字段设计**（见下方【不确定点 4】）
- **向量索引**：`HNSW` 或 `IVF_FLAT`（见下方【不确定点 5】）

### Step 6：数据插入与验证
- 批量插入（每次不超过 1000 条）
- 验证：
  - 总条数 = 4 部书的切片总数
  - 随机采样几条做语义检索，确认 Top-K 结果合理

## 需要你确认的不确定点

### ❓ 1. Milvus 部署状态
> Milvus 容器是否已经启动？如果是，请确认：
> - Milvus 版本（2.x Standalone？）
> - 暴露端口（默认 19530 / 9091？）
> - 是否需要我帮你写 `docker-compose.yml` 一键启动？

### ❓ 2. 切片策略（最关键）
> 你希望怎么切片？请选一个：
> - **A. 按章节整回目切**（每回一个 chunk，约 100~300 条/书）
>   - ✅ 语义完整，检索结果可读性强
>   - ⚠️ 长章节可能超出模型 512 token 限制（需截断）
> - **B. 固定长度滑动窗口**（如 500 字符 / chunk，重叠 50）
>   - ✅ 粒度细，检索命中率高
>   - ⚠️ 可能切断句子，上下文断裂
> - **C. 混合策略**（推荐）：先按章节切，超长章节再按段落二次切分
>   - ✅ 兼顾语义完整性和粒度
> 
> **我的建议：选 C（混合策略）**，如果你没特殊要求我就按这个做。

### ❓ 3. 文本清洗范围
> 是否需要我做以下清洗？
> - [ ] 去掉前 5 行版权/网站声明（三国、水浒、西游有，红楼已干净）
> - [ ] 去掉 HTML `<p>` 标签（三国、水浒）
> - [ ] 去掉"========简介========""========正文========"等标记
> - [ ] 水浒的"楔子"是否保留作为独立 chunk？
> 
> **我的建议：全部清洗掉，只保留章节标题 + 正文。**

### ❓ 4. Collection Schema 字段设计
> Milvus 中除了向量字段，还需要哪些元数据字段？请勾选：
> - [x] `id` — 主键（自增）
> - [x] `book_name` — 书名（如"三国演义"）
> - [x] `chapter_title` — 章节标题（如"第一回 宴桃园豪杰三结义"）
> - [x] `chapter_num` — 章节序号（如 1）
> - [x] `chunk_index` — 切片序号（如果一章被切成多段）
> - [x] `content` — 原文内容（检索后回显给用户看）
> - [ ] `word_count` — 字数
> - [ ] 其他：__________
> 
> **我的默认方案：勾选的 6 个字段全建。**

### ❓ 5. 向量索引类型
> - **HNSW**（推荐）：检索速度最快，召回率稍低但够用，适合百万级以下
> - **IVF_FLAT**：平衡型，召回率更高，适合精确检索场景
> - **FLAT**：暴力搜索，最精确但最慢，仅适合数据量 <1万
> 
> **4 部书切片后预计 500~2000 条，我推荐 HNSW。**

### ❓ 6. BGE 编码是否加前缀指令
> BGE 官方推荐给文档加前缀：`"为这个文档生成表示以用于检索：" + 正文`
> - 加前缀：检索精度更高（推荐）
> - 不加前缀：兼容性好，代码更简洁
> 
> **我的建议：加前缀。**
